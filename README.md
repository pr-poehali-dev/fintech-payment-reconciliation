# fintech-payment-reconciliation

Initial repository setup for pr-poehali-dev/fintech-payment-reconciliation
## Правила для новых платёжных интеграций (банки, эквайринг)

1. **Проверка логина/пароля при сохранении.** Перед созданием и при смене данных входа делаем безвредный
   запрос к API банка (статус несуществующего заказа/платежа). Неверные данные — ошибка, интеграция не
   сохраняется; банк недоступен — сохраняем с предупреждением. Код: `backend/integrations-create/credentials_check.py`
   (копия в `integrations-update`). Новый банк = функция `check_<slug>` + строка в `CHECKERS`.
2. **Без лишних полей для клиента.** Не просим то, что выдаёт только поддержка банка (ключи подписи и т.п.):
   подлинность уведомления подтверждаем запросом статуса заказа в банке.
3. **Подлинность вебхуков.** Т-Банк — токен по паролю терминала; Альфа — запрос статуса заказа (или ключ подписи);
   Точка эквайринг — JWT с подписью RS256 ключом банка (проверка в `tochka_acquiring_handler.py`).
4. **Сертификаты Минцифры.** Серверы российских банков подписаны ими — используем `russian_ca.py`.
5. **Чеки.** Вебхук только сохраняет платёж и корзину; чек — через сценарий «Новый платёж» в «Автоматизации».
   Новую платёжку добавить в `PROVIDERS_WITH_RECEIPT_SCENARIO` (src/components/integrations/providerFieldsConfig.ts),
   чтобы предлагался сценарий и горела иконка чека.
